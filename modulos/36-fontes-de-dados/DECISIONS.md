# Decisões — Central de Fontes

- **Servidor busca, PC é reserva (14/out/2026).** O app do Azure do SSO já lê arquivos (Files.Read.All, 02/out). Então o servidor baixa as planilhas do OneDrive/SharePoint e roda o mesmo parser do PC. As tarefas agendadas do Windows continuam funcionando, mas deixam de ser o caminho principal: PC desligado ou EDITOR_TOKEN velho no `.env` não congelam mais os dados.
- **Mesmo parser, não reescrita.** Os scripts de sync ganharam só a leitura de `FONTE_ARQUIVO`. Reescrever cada leitor em outra linguagem criaria duas verdades. Por isso a imagem do Railway ganhou pandas + openpyxl, para os leitores em Python.
- **Hash em vez de "data de modificação".** O Google não devolve data de modificação pelo link de exportação, e o OneDrive às vezes muda a data sem mudar o conteúdo. Planilha com o mesmo sha256 só registra "conferida"; a "última atualização" do dado fica intacta (é o que a tela mostra).
- **"Atualizar agora" força o reprocessamento.** O clique manual roda o parser mesmo com hash igual. Serve para depois de corrigir parser ou banco. Limite de 1 clique por minuto por fonte.
- **Só três tipos de link** (OneDrive `onedrive:/…`, SharePoint/1drv, Google Sheets), validados por host. Quem cola o link é só o super admin, e mesmo assim o servidor não vira um buscador de URL qualquer (risco de SSRF).
- **Caminho padrão inexistente = "aguarda", não "erro".** Os caminhos padrão são os do OneDrive do PC do Rudá. Se a pasta não estiver ali (ou o atalho não resolver), a tela pede o link em vez de acender alerta vermelho. O motor tenta de novo 1x por dia.
- **Atalho de pasta compartilhada resolvido no motor.** "Adicionar atalho a Meus arquivos" aparece como pasta no PC, mas o caminho direto no Graph não atravessa o atalho. O motor acha o `remoteItem` e continua no drive de origem.
- **JSON gerado no servidor fica guardado no banco.** Os parsers escrevem em `public/api/` (todo o código lê de lá), e um deploy volta a pasta para a versão do repositório. O motor guarda o arquivo em `app_blobs` e devolve no boot se for mais novo que o do repositório. É o mesmo mecanismo que o `events.json` já usava.
- **Alerta só do que já teve dado.** Fonte que nunca atualizou fica só em `/fontes`; o alerta é para "parou" ou "quebrou". Regra do Módulo 34: nada de aviso a partir de dado inexistente.
- **Fontes do time todo (cadastro do time, metas) cobram a Gestão.** Na tela continuam visíveis para o time; o alerta de revisão não vai para todo mundo.
- **Endereço do arquivo e link só para o super admin.** O resto do time vê nome, quem editou e quando, mas não o caminho no OneDrive.
- **CRM sai do repositório público daqui em diante.** O snapshot de leads do Zoho passa a ser gerado no servidor (API) e guardado no banco. Nenhum número novo de CRM vai para o git. O que já está no histórico depende de tornar o repositório privado.
- **Zoho: campo da origem da oportunidade corrigido.** `Marketing_Intelligence__Opportunity_Source` não existe mais (a consulta voltava INVALID_QUERY). O campo é `Origem_da_Oportunidade`. Entram `MKT (EPI-USE)` e `SDR`; `MKT (Valcann)` fica fora (outra empresa do grupo). Conferido no Zoho em 14/out: 105 + 54 = 159 oportunidades.
- **Redatoria: abas de mês detectadas.** A lista era fixa (jan–jun/26), e as abas que a Redatoria criou depois (Jul26, AGO26, Set26) nunca entravam. A aba AGO26 tem temas sem data: o leitor ignora (não inventa data).
